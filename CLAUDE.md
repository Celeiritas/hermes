# Hermes – notes for Claude Code

Hermes carries files and short messages between the devices of one tailnet, and fetches from allowlisted sources. **It carries and never runs, unpacks or installs anything**: it never opens archives, never sets an exec bit, never decides whether a file is allowed (Janus does) and never deploys (Zeus does). `docs/design.md` is the spec; read the section an issue names before changing anything.

## Map
- `hermes/` – the package, Python 3 standard library only (it may call `git` and `tailscale`). `cli.py` is the command line; each issue adds its command (`receive`, `door`, `send`, `keys`, `fetch/` ...). `config.py` reads, validates and explains `routes.json` (`config.load()` raises `ConfigError`; `config.check()` returns errors and warnings for `hermes check-config`); placeholders come from `realm.json` with Mentor's public defaults. `receive.py` is the ssh forced command (`ping`, `put`: stream, hash, check, `meta.json`, one rename into `in/`; failures set aside in `failed/`). `keys.py` edits only `hermes:<device>` lines in `~/.ssh/authorized_keys`, backup first (`docs/keys.md`). `door.py` is the delivering side: `hermes door` asks Janus (`docs/janus-contract.md`), delivers, quarantines, skips or holds, and `retry`, `release`, `discard`; `verdict.json` is saved into the arrival before anything moves, so an interrupted run finishes cleanly. `log.py` keeps the records (`docs/files.md`): the monthly JSONL log, `hermes log`, `hermes status`, the Argus alert file and `hermes ack`. `send.py` is the other direction (`docs/both-ways.md`): `hermes send` (a hardlink staged with `direction: out`, the same door, then `tailscale file cp`; the outbox waits for a sleeping device), `hermes message` (note, link, magnet) and `hermes collect` (`hermes-taildrop.timer`: retry the outbox, `tailscale file get` without `--wait`, the door). `hermes.version()` reads `VERSION`.
- `scripts/build.sh` → `dist/hermes`, one file: a zipapp with a `python3` shebang, installed as `~/.local/bin/hermes` on the server. `scripts/check-private.sh` scans for personal data (staged changes, a range, `--tree`, `--history`); `scripts/install-hooks.sh` runs it before every push. Both are copied unchanged from argus-ui.
- `clients/windows/` – `hermes.ps1`, PowerShell 5 only (no Python on the PC). `plugin/` – the Elaia server plugin `delivery`. `units/` – systemd templates (`hermes-door.path` watches every stage's `in/`, `hermes-door.service` is a one-shot; `hermes-taildrop.timer` runs `hermes collect` every 2 minutes). `clients/dolphin/` – the right-click "send to {{PC}}" menu. `examples/routes.example.json` – placeholders only. `docs/` – design and the file formats.
- `tests/` – stdlib `unittest`, run by `bash tests/run.sh`. `tests/fixtures/janus` is a fake Janus that keeps to the contract in design §3; door tests use it. `tests/fixtures/tailscale` fakes `tailscale whois --json`, `file cp` and `file get` (`$HERMES_TAILSCALE` points Hermes at it; `$HERMES_FAKE_DEVICE` and `$HERMES_FAKE_TAILDROPS` are its device and its waiting files). There is no real Janus in this repo.
- `.github/workflows/` – `tests.yml` and `check-private.yml` (the generic privacy check) run on every pull request.

## Test before you say it works
`bash tests/run.sh` (needs only python3, bash and git). `bash scripts/build.sh && ./dist/hermes --version` must work on a clean Linux checkout with only Python 3. Add a test under `tests/` for every feature.

## Rules
- **Hermes carries, never runs.** Nothing from config or from a delivery is ever executed, unpacked, imported or made executable. Doorbells (`after`) come from a fixed list in code. A delivery that Janus has not passed is never delivered.
- **Placeholders, never real names.** Public text (code, docs, examples, tests, commit messages) says `{{SERVER}}`, `{{PC}}`, `{{PHONE}}`, `{{SSH}}`, `{{HOME_PC}}`, `{{HOME_SERVER}}`, never a real device, user, path, host or account. The owner's real config lives in the private realm repo. Your own notes go in `CLAUDE.local.md` (gitignored).
- **Run `bash scripts/check-private.sh` before every push** (once per clone: `bash scripts/install-hooks.sh` makes it automatic). Fix what it finds; `private-ok` on a line is only for a deliberate example of a pattern, such as Tailscale's fixed ranges.
- **Branches are `<area>/<topic>`** (`door/quarantine`, `docs/design`), always off `main`, never stacked. One issue → one pull request, small commits with clear messages. Pull requests merge themselves when CI is green: `main` requires the `tests` and `check-private` checks, so right after `gh pr create` run `gh pr merge <n> --auto --merge` and move on; the owner reads pull requests after the fact. Never push `main` directly.
- **Bump `VERSION` and add a `CHANGELOG.md` entry** for every change that ships. Before 1.0 the minor number is the milestone (the issue's label: v0.1 = the door, v0.2 = both ways …), so work inside a milestone bumps the patch (0.1.2 → 0.1.3) and the first change of the next milestone bumps the minor (→ 0.2.0).
- Standard library only on the server; PowerShell 5 only on the PC. If npm is ever used for test tooling, commit `package-lock.json`.
- Never commit keys, `jellyfin.key`, `secret.env`, logs, quarantine contents or sound files.
